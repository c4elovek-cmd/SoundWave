# SoundWave

Десктопный клиент **SoundCloud** в стиле Spotify. Оранжевая тема, смена оформления, тексты песен с караоке, свои темы, глобальные медиа-клавиши, системный трей.

## Что внутри

- **Интерфейс в стиле Spotify** — сайдбар, основной контент, панель плеера, панель очереди
- **Вход в аккаунт SoundCloud** — одно окно входа, два способа внутри него:
  - настоящая страница `soundcloud.com/signin` (пароль вводится на самом SoundCloud)
  - ручной импорт cookies из браузера (Cookie-Editor / EditThisCookie), с автопарсингом форматов
- **Не больше двух окон** — главное окно и одно окно входа, которое переиспользуется
- **Музыка** — лайки, загрузки, плейлисты, поиск треков / артистов / плейлистов
- **Моя волна** — бесконечный поток рекомендаций из лайков, подписок, похожих треков и жанров; три режима, дизлайки и автодоливка очереди
- **Популярное без входа** — на главной гостю показывается charts SoundCloud
- **Плеер** — play/pause, seek, громкость, shuffle, повтор (все / один), очередь
- **Тексты песен** — подтягиваются с Genius, кешируются и открываются в боковой панели
- **Караоке** — точная синхронизация строк из LRCLIB или примерная по длительности трека; активная строка подсвечивается и прокручивается, клик по строке перематывает трек
- **Караоке на весь экран** — отдельный режим: крупная активная строка, размытая обложка, управление и прогресс; окно можно развернуть на весь монитор, `Esc` возвращает всё на место
- **Панель настроек** — внешний вид, текст и караоке, плеер, Discord, локальный API; всё сохраняется между запусками
- **Свои шрифты** — импорт `.ttf` / `.otf` / `.woff` / `.woff2` из файла, шрифт сразу доступен в тексте песни и в полноэкранном караоке
- **Discord Rich Presence** — показывает в профиле Discord, что сейчас играет (нужен свой Client ID приложения)
- **Локальный API для агентов** — HTTP-сервер на `127.0.0.1`, которым управляют плеером, поиском, очередью, текстами и караоке
- **Шрифт текста** — Inter, Georgia, Consolas или Trebuchet, размер 12–22 px, настройки запоминаются
- **Четыре встроенные темы + свои** — тёмная (SoundCloud Orange), светлая, фиолетовая, зелёная; свою тему можно собрать из любого акцента и светлой/тёмной основы
- **Горячие клавиши** — `Space` играть/пауза, `Shift+←/→` переключение, `↑/↓` громкость, `M` mute, `Ctrl+F` поиск
- **Медиа-клавиши** и **системный трей** — сворачивается в трей, управление из контекстного меню
- **Никакого стандартного меню** — окно приложения без полосы `File / Edit / View / Window / Help`

## Как это работает без официального API

Официальный developers API SoundCloud закрыт для новичков, поэтому клиент ходит в **внутреннее API веб-версии** (`api-v2.soundcloud.com`):

1. `client_id` извлекается из JS-бандлов soundcloud.com и кешируется в main-процессе
2. все запросы идут из **main-процесса** — там нет CORS-ограничений и можно передать заголовки `Cookie` и `Authorization` (в renderer браузер заголовок `Cookie` вырезает, а без `Authorization: OAuth <token>` внутренний API отдаёт 401)
3. cookies живут в отдельном разделе сессии `persist:soundcloud`, общем для главного окна и окна входа
4. ссылка на аудио собирается цепочкой: `/tracks/{id}` → манифест потока → подписанный URL на CDN, который играется напрямую

Приватные коллекции лежат по путям `/users/{id}/likes`, `/users/{id}/followings`, `/users/{id}/playlists` и `/users/{id}/tracks` — вариантов `/me/likes` и т.п. в `api-v2` не существует (404).

Формат потока выбирается автоматически: если трек отдаётся как progressive-MP3, играет обычный `<audio>`, если SoundCloud отдаёт только HLS-манифест, подключается `hls.js` (Chromium не умеет HLS нативно).

> SoundCloud считает лайки по-своему: счётчик `likes_count` может быть больше, чем число треков, которые отдаёт API. Приложение показывает все доступные треки и честно пишет, сколько лайков API не отдаёт.

> В выдачу поиска SoundCloud иногда подмешивает профили пользователей (`kind=user`) — у них нет ни названия трека, ни поля `user`. Клиент их отфильтровывает, а любые ошибки рендера ловит `ErrorBoundary`: вместо чёрного окна показывается сообщение и кнопка перезагрузки. Сетевые запросы повторяются до трёх раз — при старте соединение иногда рвётся.

Авторизация:
- **через окно входа** — приложение открывает `soundcloud.com/signin` в отдельном окне; после редиректа на `/discover` (или `/you`) забираются cookies домена `.soundcloud.com`, окно закрывается, сессия подхватывается главным окном
- **вручную** — пользователь экспортирует cookies расширением и вставляет в то же окно входа; парсер понимает строку заголовка, JSON Cookie-Editor и Netscape `cookies.txt`. Импортированные cookies пишутся в ту же сессию и сразу проверяются запросом `/me`

> Окно входа одно и переиспользуется: оба способа входа живут внутри него, поэтому приложение никогда не открывает больше двух окон.

> ⚠️ Проект не является официальным клиентом SoundCloud. Использование внутреннего API может нарушать Terms of Service — используй на свой риск.

## Моя волна

Бесконечный поток рекомендаций в духе «Моей волны» Яндекс.Музыки. Волна собирается из того, что уже есть в аккаунте, и не заканчивается: когда очередь подходит к концу, плеер доливает следующую порцию.

| Источник | Эндпоинт | Что даёт |
|---|---|---|
| Похожие треки | `/tracks/{id}/related` | треки рядом с лайкнутыми |
| Подписки | `/users/{id}/tracks` | новое у артистов, на которых подписан |
| Любимые артисты | `/users/{id}/tracks` | те, кого чаще всего лайкают |
| Жанры лайков | `/search?type=tracks` | свежее в любимых жанрах |
| Тренды | `/charts?kind=trending` | то, что слушают все |

Каждый источник даёт треки со своим весом, дальше идёт взвешенная случайная выборка — поэтому два запуска подряд не повторяются. Режимы меняют пропорции:

- **Знакомое** — больше похожего на лайки;
- **Всё вместе** — любимое и новое вперемешку;
- **Новое** — больше незнакомых артистов и трендов.

В волну не попадают неиграбельные треки (`policy: SNIP` или `BLOCK`, `streamable: false`), уже прослушанное (история в `localStorage`, последние 300 треков) и дизлайкнутое. Два дизлайка треков одного артиста убирают артиста из волны. Очередь волны живёт в `playerStore`, поэтому «вперёд», «назад» и автопереход работают как с обычным плейлистом, а `refill` дописывает новую порцию в конец.

## Тексты и караоке

Кнопка с текстом в панели плеера открывает боковую панель. Текст ищется на Genius через публичный поиск (`/api/search/multi`), из страницы вытаскиваются строки из `div[data-lyrics-container="true"]`. Кандидаты ранжируются: совпадение названия и артиста важнее, переводы и каверы отбрасываются. Результат кешируется в `localStorage` на 6 часов.

В режиме караоке приложение запрашивает LRCLIB (`/api/search`) по названию, артисту и длительности. Если найден LRC с точными метками времени, строки выравниваются с текстом Genius по нормализованному тексту. Если LRC нет или совпало слишком мало строк, строки раскладываются по длительности трека с весом по количеству символов — это честная оценка, а не точная синхронизация.

- зелёная точка — точные тайминги LRCLIB;
- серая — примерная раскладка;
- пульсирующая оранжевая — идёт поиск.

Клик по строке в караоке перематывает трек на её начало. Шрифт и размер текста выбираются в тулбаре панели и сохраняются между запусками.

### Караоке на весь экран

Кнопка с микрофоном в панели плеера (и пункт «Во весь экран» в тулбаре текста) открывают отдельный полноэкранный режим:

- активная строка — крупно, с подсветкой; соседние строки уходят в полупрозрачный фон;
- на фоне — размытая обложка трека, сверху название и исполнитель, справа бейдж точности синхронизации;
- внизу — пауза, следующий трек, полоса прогресса с перемоткой и регулировка размера шрифта;
- `Space` — пауза, `Esc` — выход;
- кнопка «на весь экран» переводит само окно в полноэкранный режим монитора; выход из него по `Esc` закрывает караоке.

Текст для этого режима подтягивается отдельно: караоке можно открыть, не открывая боковую панель.

## API для агентов

Приложение поднимает локальный HTTP-сервер на `127.0.0.1:4783` (если порт занят — следующий свободный). Данные для подключения пишутся в `%APPDATA%\soundwave\agent-api.json`:

```json
{
  "url": "http://127.0.0.1:4783",
  "token": "…",
  "openapi": "http://127.0.0.1:4783/api/openapi.json"
}
```

Все защищённые запросы требуют заголовок `Authorization: Bearer <token>`; `GET /api/health` и `GET /api/openapi.json` открыты. Сервер слушает только loopback, проверяет заголовок `Host` и не отдаёт CORS-заголовки — из браузера до него не достучаться.

```bash
TOKEN=$(node -p "require(process.env.APPDATA + '/soundwave/agent-api.json').token")

curl http://127.0.0.1:4783/api/state -H "Authorization: Bearer $TOKEN"
curl "http://127.0.0.1:4783/api/search?q=ic3peak&limit=3" -H "Authorization: Bearer $TOKEN"
curl http://127.0.0.1:4783/api/play -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"query":"IC3PEAK смерти больше нет"}'
curl http://127.0.0.1:4783/api/control -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"action":"pause"}'
```

| Метод и путь | Что делает |
|---|---|
| `GET /api/health` | проверка, что приложение живо |
| `GET /api/openapi.json` | схема OpenAPI 3.1 для самописания агента |
| `GET /api/state` | трек, позиция, громкость, тема, очередь, текущий экран |
| `GET /api/search?q=&type=&limit=` | поиск треков, артистов, плейлистов |
| `POST /api/play` | включить трек по `id`, `url` или `query` |
| `POST /api/control` | `play`, `pause`, `toggle`, `next`, `prev`, `seek`, `volume`, `mute`, `shuffle`, `repeat` |
| `GET/POST /api/queue` | очередь: список, добавить, убрать, очистить |
| `GET /api/lyrics?trackId=&synced=` | текст Genius и синхронизация LRCLIB с активной строкой |
| `GET /api/likes`, `GET /api/playlists`, `GET /api/playlist/{id}` | библиотека |
| `GET /api/track/{id}` | карточка трека |
| `POST /api/navigate` | открыть экран: `home`, `wave`, `search`, `likes`, `playlist`… |
| `POST /api/karaoke` | открыть или закрыть караоке на весь экран |
| `POST /api/show` | показать и сфокусировать окно |

Команды из main-процесса уходят в renderer по IPC и выполняются над сторами, поэтому агент видит ровно то же состояние, что и интерфейс.

## Свои темы

В меню «Тема» есть пункт «Своя тема». В редакторе задаются название, основа (тёмная или светлая) и акцент: цветовой пикер, hex-поле или готовые пресеты. Перед сохранением показывается мини-предпросмотр.

Свои темы хранятся в `localStorage` (`sw-custom-themes`), выбранная тема — в `electron-store` как `custom:<id>`. При старте приложение поднимает тему из конфига и применяет сохранённый акцент; если тема удалена, откатывается на тёмную. Кнопка-карандаш рядом с темой открывает её на редактирование, там же — удаление.

## Настройки

Пункт «Все настройки…» в меню тем открывает единую панель. Вкладки:

| Вкладка | Что настраивается |
|---|---|
| Внешний вид | тема, анимации, плотность интерфейса, свёрнутый сайдбар при запуске |
| Текст и караоке | шрифт и размер текста, караоке по умолчанию, точная синхронизация, свои шрифты |
| Плеер | громкость, перемешивание и повтор при запуске |
| Discord | вкл/выкл Rich Presence, Client ID, имя большой картинки, статус подключения |
| API для агентов | вкл/выкл, порт, токен (показать, скопировать, перевыпустить) |
| О программе | версия, папка данных, репозиторий, сброс настроек |

Настройки лежат в `localStorage` под ключом `sw-settings` и применяются на лету: анимации и плотность — через классы на `documentElement`, громкость, повтор и перемешивание — в плеере, шрифты — в панели текста и в полноэкранном караоке.

### Свои шрифты

Кнопка «Импортировать шрифт» открывает системный диалог. Файл копируется в `%APPDATA%\soundwave\fonts`, а renderer регистрирует его через `FontFace` и добавляет в `document.fonts` — после этого шрифт доступен и в боковой панели текста, и в полноэкранном караоке. Удаление шрифта убирает и файл, и регистрацию.

## Discord Rich Presence

Приложение умеет показывать в профиле Discord, что сейчас играет: название трека, исполнителя и время с начала трека.

Протокол Discord RPC — это локальный именованный канал (`\\.\pipe\discord-ipc-N`), поэтому в проекте лежит свой небольшой клиент (`electron/discord-rpc.ts`) без внешних зависимостей: handshake, кадры `[длина][опкод][JSON]`, переподключение при перезапуске Discord и снятие активности при выходе.

Rich Presence требует **своего приложения в Discord**: Client ID берётся на [discord.com/developers/applications](https://discord.com/developers/applications) и вставляется в настройках. В приложении также нужно загрузить картинку и указать её имя (обычно `soundwave`) в поле «Имя большой картинки» — тогда в профиле будет обложка. Работает только с настольным Discord для ПК.

## Скачать и релизы

Готовые сборки для Windows — в [GitHub Releases](https://github.com/c4elovek-cmd/SoundWave/releases/latest): установщик NSIS и portable-версия.

Релиз собирается командой:

```bash
npm run package
```

Артефакты кладутся в `release/`. Пуш тега `v*` запускает GitHub Actions (`.github/workflows/release.yml`), который собирает установщик и прикрепляет его к релизу.

## Запуск

```bash
# установка
npm install

# сборка и запуск
npm run electron
```

Для разработки с горячей перезагрузкой:

```bash
npm run dev        # vite dev-сервер (только UI)
```

## Структура

```
electron/
  main.ts            # главное окно, трей, медиа-клавиши, окно входа, API-прокси, IPC
  preload.ts         # безопасный мост contextBridge
  agent-api.ts       # локальный HTTP-сервер для агентов
  discord-rpc.ts     # клиент Discord Rich Presence (именованный канал)
src/
  App.tsx            # роутинг видов, топ-бар, панель очереди
  components/
    Layout/          # каркас
    Sidebar/         # навигация, список плейлистов, меню тем
    Player/          # панель плеера, горячие клавиши
    Lyrics/          # панель текста, караоке, полноэкранный режим, шрифты
    Settings/        # панель настроек
    ThemeEditor/     # редактор своей темы
    Track/           # трек-строка и карточка
  pages/
    HomePage.tsx     # главная: популярное (гость), лайки, артисты, плейлисты
    WavePage.tsx     # «Моя волна»: запуск, режимы, очередь, дизлайки
    SearchPage.tsx   # поиск с debounce и вкладками
    LibraryPage.tsx  # лайки / загрузки с пагинацией
    AuthPage.tsx     # выбор способа входа (в окне входа)
    ManualAuthPage.tsx # ручной импорт cookies (в том же окне)
  stores/            # zustand: appStore, playerStore, waveStore, lyricsStore, settingsStore
  lib/
    soundcloud-api.ts # обёртка внутреннего API через IPC
    wave.ts           # движок рекомендаций «Моей волны»
    lyrics.ts         # разбор LRC, выравнивание и тайминги караоке
    fonts.ts          # встроенные и свои шрифты, регистрация FontFace
    themes.ts         # свои темы, цветовая математика, применение
    agentBridge.ts    # выполнение команд агента над сторами
  styles/
    themes.css       # встроенные темы на CSS-переменных
```
