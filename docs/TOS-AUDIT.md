# Аудит соответствия Terms of Service

Проверка приложения SoundWave на соответствие правилам SoundCloud, Discord и
сторонних сервисов, которые оно использует. Дата проверки: 20 октября 2026.

Документ не является юридической консультацией — это технический разбор
поведения кода и его рисков. Раздел «Что делаем» составлен по исходникам
приложения, а не по предположениям.

---

## 1. Что приложение делает технически

| Область | Как реализовано | Где в коде |
|---|---|---|
| Доступ к каталогу SoundCloud | Внутренний API `api-v2.soundcloud.com` | `electron/main.ts` (`sc-request`, `sc-write`) |
| Идентификатор приложения | `client_id` вытаскивается из JS-бандла soundcloud.com | `getClientId()` |
| User-Agent | подменяется на браузерный | `BROWSER_UA` |
| Авторизация | cookies сессии пользователя + `oauth_token` из них | `getCookieHeader()`, `getAccessToken()` |
| Аудио | только стриминг подписанного CDN-URL, файлы не сохраняются | `sc-resolve-stream` |
| Лайки | `PUT/DELETE .../system_playlist_likes/...` от имени пользователя | `sc-toggle-like` |
| Тексты песен | HTML-страница Genius, парсинг `div[data-lyrics-container]` | `getGeniusLyrics()` |
| Караоке | официальный публичный API LRCLIB | `getSyncedLyrics()` |
| Discord | локальный IPC-канал `discord-ipc-N`, протокол Discord RPC | `electron/discord-rpc.ts` |
| Локальный API | HTTP на `127.0.0.1`, Bearer-токен, без CORS | `electron/agent-api.ts` |

Дополнительно в коде: кэш текстов Genius на 6 часов (до 200 записей), кэш
LRCLIB на 6 часов, троттлинг запросов к SoundCloud (не больше 3 одновременных
и не чаще одного в 150 мс), повтор сетевых запросов до трёх раз.

## 2. SoundCloud

### Что говорят правила

- [Условия использования SoundCloud](https://soundcloud.com/terms-of-use)
  регулируют сайт, приложения, плееры, виджеты, инструменты и **все API, которые
  дополнительно регулируются отдельными API-условиями**.
- Раздел про плееры и виджеты: официальные плееры SoundCloud нельзя
  использовать для создания нового сервиса музыкального стриминга.
- [Условия использования API](https://developers.soundcloud.com/docs/api/terms-of-use)
  требуют использовать API с `client_id`, выданным SoundCloud через
  developer portal, и ограничивают коммерческое использование данных.

### Риски

| # | Что делаем | Оценка | Комментарий |
|---|---|---|---|
| 2.1 | Используем внутренний `api-v2` вместо официального API | **средний** | Формально нарушаем API-условия: официальный `client_id` не запрашивали, а идентификатор веб-клиента добыли из бандла. Реально это то, что делают все неофициальные клиенты, но правила это запрещают. |
| 2.2 | Подменяем User-Agent на браузерный | **средний** | Обход технической меры: без «браузерного» UA API отдаёт 401. Формально — circumvention. |
| 2.3 | Работаем от сессии пользователя (cookies + OAuth) | **низкий** | Это собственная сессия пользователя, приложение не обходит авторизацию и не крадёт чужие данные. |
| 2.4 | Пишем в аккаунт (лайки) | **низкий** | Обычная пользовательская функция, тот же эндпоинт использует веб-клиент. |
| 2.5 | Аудио не скачиваем, только стримим | **нет риска** | Копирование треков не реализовано — это снимает самый частый претензий по авторским правам. |
| 2.6 | Нагрузка на API (волна, автодоливка, ретраи) | **низкий** | Добавлен троттлинг: ≤3 одновременных запроса, интервал 150 мс, кэши текстов. |
| 2.7 | Обход ограничений на коммерческое использование | **нет** | Приложение бесплатное, данные не перепродаются и не агрегируются. |

### Что можно сделать

1. **Оставить как есть, но честно предупредить пользователя** — дисклеймер в
   README и в приложении уже есть. Это осознанный технический выбор: официальный
   API закрыт для новых клиентов, иначе приложение просто не существовало бы.
2. **Снизить «палечность»**: не перебирать сотни треков подряд, держать
   кэши (сделано), не запускать волну в фоне без пользователя (стоит проверить).
3. **Отказаться от вытаскивания `client_id` из бандла** — тогда клиент перестанет
   работать; оставить как осознанный компромисс и не выносить в публичный код
   отдельную «инструкцию по обходу».

## 3. Discord

### Что говорят правила

- [Условия использования Discord](https://discord.com/terms) запрещают автоматизацию
  от имени пользователя (self-bot) и использование Discord в обход правил платформы.
- [Политика Discord для разработчиков](https://discord.com/developers/docs/policy)
  требует: не запускать процессы от имени пользователя без его разрешения, не
  собирать учётные данные, не вводить в заблуждение относительно приложения,
  соблюдать лимиты и не нарушать правила сообщества через своё приложение.
- Rich Presence — штатный механизм «сейчас играет», для него нужно
  зарегистрированное приложение с собственным `client_id`.

### Риски

| # | Что делаем | Оценка | Комментарий |
|---|---|---|---|
| 3.1 | Rich Presence через локальный IPC-канал | **нет риска** | Это ровно тот протокол, который использует официальный Discord SDK; никакой автоматизации аккаунта. |
| 3.2 | Client ID | **нет риска** | Приложение зарегистрировано на аккаунт владельца, имя «SoundWave» совпадает с брендом, чужой `client_id` не используется. Свой можно вписать в настройках. |
| 3.3 | Данные в presence | **нет риска** | Уходит только название трека и исполнитель. Ничего личного, ничего не продаётся и никуда не передаётся. |
| 3.4 | Частота обновлений | **нет риска** | `SET_ACTIVITY` — раз на смену трека плюс heartbeat раз в минуту. Лимиты Discord не задеваются. |
| 3.5 | Активность включается по желанию | **нет риска** | Есть переключатель в настройках: по умолчанию включено, но выключается в один клик — это «явное разрешение пользователя». |
| 3.6 | Занимаем единственный слот активности | **не нарушение, но нюанс** | Discord показывает только одну активность: если её заняло другое приложение (например, Modrinth), наша пропадает до следующего обновления.

### Что можно сделать

1. Завести своё приложение Discord «SoundWave» и вшить его Application ID в
   код (в настройках оставить возможность заменить своим).
2. Загрузить в приложение Discord ассет `soundwave` — тогда в профиле будет
   обложка приложения, а не заглушка.
3. **Не** переносить в проект чужие `client_id` — это то, что мы убрали.

## 4. Genius и LRCLIB

| Сервис | Что делаем | Оценка | Комментарий |
|---|---|---|---|
| Genius | Ищем через публичный эндпоинт поиска, разбираем HTML страницы песни | **средний** | У Genius нет публичного API для текстов, официальный `api.genius.com` отдаёт только метаданные. Формально это scraping, но частота низкая: кэш 6 часов, один поиск и одна страница на трек, запросов на трек — несколько вариантов названия. |
| LRCLIB | Официальный публичный API, `User-Agent` указываем, как просят | **нет риска** | LRCLIB прямо рассчитан на сторонние клиенты. |

## 5. Не-ToS, но важные риски

| # | Риск | Оценка | Что сделано / что сделать |
|---|---|---|---|
| 5.1 | `oauth_token` и cookies хранятся открытым текстом в `%APPDATA%\soundwave\soundwave-config.json` | **средний** | Файл не в репозитории, но попадает в бэкапы. Токен даёт полный доступ к аккаунту. Стоит шифровать (DPAPI) или хранить в Credential Manager. |
| 5.2 | Файл `agent-api.json` с токеном локального API лежит в открытом виде | **средний** | Любой локальный процесс может его прочитать и управлять плеером. Сервер слушает только `127.0.0.1`, проверяет `Host` и не отдаёт CORS — но сам файл секретный. |
| 5.3 | Локальный API для агентов | **низкий** | Ограничен loopback, требует Bearer, ошибки не логируют токены. |
| 5.4 | Права на тексты песен | **средний** | Тексты показываются пользователю в его клиенте, копирование треков не реализовано. |
| 5.5 | Логи | **нет риска** | Проверено: в `main.log` не попадают cookies и токены — только общие сообщения. |

## 6. Итог

- **Явных нарушений, которые нельзя объяснить**, нет: приложение работает с
  сессией самого пользователя, не обходит авторизацию, не копирует музыку и не
  рассылает данные.
- **Главные зоны риска** — использование внутреннего API вместо официального,
  подмена User-Agent и чтение HTML Genius. Все три — осознанный компромисс
  ради работоспособности: официальный API закрыт для новых клиентов.
- **Discord** — в полном порядке: своё приложение, свой `client_id`, штатный
  протокол, в presence только название трека, выключается в настройках.
- **Обязательное действие** — вшить Client ID собственного приложения Discord
  (сделано) и загрузить в него иконку (нужна загрузка через портал).
- **Желательное** — шифровать сессионные cookies и токен локального API, а в
  README держать дисклеймер о неофициальном клиенте.
