# SoundWave — Десктопный клиент SoundCloud

## Концепция и видение

Нативный десктопный клиент SoundCloud с интерфейсом в стиле Spotify. Приложение предоставляет полный доступ к аккаунту SoundCloud — трекам, плейлистам, загрузкам, подпискам — без браузера. Ощущение: быстрый, лёгкий, минималистичный, но с характером SoundCloud (оранжевый, музыка, свобода).

Целевой пользователь — слушатель, который хочет удобство настольного клиента (горячие клавиши, системный трей, медиа-клавиши) без зависимости от браузера.

- **Основной шрифт:** `Inter` — читаемый, нейтральный, как у Spotify

- **Размеры:**
  - XL: 24px (заголовки страниц)
  - L: 18px (секции)
  - M: 14px (основной текст)
  - S: 12px (мета-данные, время)
- **Line-height:** 1.4 для текста, 1.2 для заголовков

### Пространственная система

- **Базовый модуль:** 4px
- **Отступы:** 8px, 12px, 16px, 24px, 32px, 48px
- **Радиусы:**
  - Кнопки/инпуты: 4px
  - Карточки: 8px
  - Аватары: 50%
  - Крупные элементы: 12px
- **Тени:** минимальные, только для elevated surfaces

### Анимации

- **Длительность:** 150ms для ховер-эффектов, 300ms для переходов
- **Easing:** `cubic-bezier(0.4, 0, 0.2, 1)` — Material motion
- **Hover:** scale(1.02) для карточек
- **Page transitions:** fade 200ms

## Функциональность

### Авторизация (вход в аккаунт)

**Flow:**
1. Пользователь жмёт «Войти» — открывается **одно** окно входа (всего в приложении не больше двух окон)
2. В окне выбирается способ:
   - «Войти через SoundCloud» — в это же окно грузится настоящая `soundcloud.com/signin`, пароль вводится на самом SoundCloud
   - «Войти вручную» — в это же окно переключается форма для вставки cookies
3. После успешного входа SoundCloud уводит на `/discover` (или `/you`) — приложение забирает cookies домена `.soundcloud.com` из раздела сессии `persist:soundcloud`
4. Cookies кладутся в общий раздел сессии, окно входа закрывается, главное окно получает профиль
5. При последующих запусках — сессия восстанавливается автоматически (раздел персистентный), вход заново не нужен

**Реализация:**
- Окно входа с настоящей страницей soundcloud.com; пароль приложению не видно
- Запасной путь: ручной импорт cookies (строка заголовка, JSON Cookie-Editor, Netscape cookies.txt) — cookies пишутся в тот же раздел сессии и проверяются запросом `/me`
- Дальнейшие запросы — через внутренний API SoundCloud из main-процесса (в renderer нельзя передать заголовок `Cookie`)

### Воспроизведение

- Play/Pause/Next/Previous
- Seek (клик на progress bar)
- Volume control
- shuffle/repeat
- Queue management (add, remove, reorder)
- Keyboard shortcuts

### Навигация

- Поиск по трекам, исполнителям, плейлистам
- Переход по ссылкам в треках (исполнитель, альбом)
- Browser back/forward

### Моя волна

- Включение/остановка бесконечного потока рекомендаций
- Три режима: «Знакомое», «Всё вместе», «Новое» — меняют веса источников
- Очередь доливается автоматически, когда треки заканчиваются
- Дизлайк убирает трек из очереди; два дизлайка артиста исключают его из волны
- История прослушанного и дизлайки хранятся в `localStorage`
- Очередь волны — это очередь `playerStore`: next/prev/автопереход работают как обычно

### Тексты песен и караоке

- Кнопка «Текст песни» в панели плеера открывает правую панель; одновременно с очередью панель не открывается
- Текст ищется на Genius: публичный `GET https://genius.com/api/search/multi?per_page=5&q=...`
- Из страницы трека извлекаются блоки `div[data-lyrics-container="true"]` (с заменой `<br>` на переводы строк)
- Кандидаты ранжируются по совпадению названия и артиста; переводы, каверы и ремиксы штрафуются; при совпадении меньше 80 символов результат считается ненайденным
- Результат кешируется в `localStorage` (`sw-lyrics-cache`) на 6 часов, ошибки не кешируются
- Караоке: точные тайминги запрашиваются у LRCLIB (`GET https://lrclib.net/api/search?track_name=...&artist_name=...`) с обязательным `User-Agent`
- LRC разбирается с поддержкой нескольких меток времени в строке; строки выравниваются с текстом Genius по нормализованному тексту (регистр, пунктуация, пробелы)
- Если совпало меньше 40% строк, включается оценка: строки раскладываются между началом и концом трека с весом по длине строки
- Активная строка определяется по `audio.currentTime` через `requestAnimationFrame`; состояние меняется только при переходе на новую строку
- Активная строка подсвечивается акцентом, панель плавно прокручивается к ней; клик по строке перематывает трек на её начало
- Индикатор синхронизации: зелёный — точные тайминги LRCLIB, серый — оценка, пульсирующий оранжевый — идёт поиск

### Шрифты текста

- Четыре встроенных варианта: Inter (sans), Georgia (serif), Consolas (mono), Trebuchet (rounded)
- Свои шрифты: импорт `.ttf` / `.otf` / `.woff` / `.woff2` через системный диалог
- Файл шрифта копируется в `%APPDATA%\soundwave\fonts`, метаданные — в `electron-store` (`customFonts`)
- Renderer регистрирует шрифт через `FontFace` и добавляет его в `document.fonts`; шрифт доступен и в панели текста, и в полноэкранном караоке
- Размер 12-22 px, в караоке к размеру прибавляется 3 px (максимум 28 px)
- Выбор хранится в `localStorage` (`sw-settings`), старые отдельные ключи (`sw-lyrics-font`, `sw-lyrics-font-size`, `sw-lyrics-karaoke`) переносятся автоматически

### Свои темы

- В меню «Тема» — пункт «Своя тема»; редактор открывается модальным окном
- Параметры: название (до 32 символов), основа `dark | light`, акцент `#rrggbb`
- Акцент выбирается пикером, hex-полем или одним из 10 пресетов; есть живой предпросмотр
- Производные цвета считаются из акцента: `--accent-hover` (осветление 18%), `--accent-pressed` (затемнение 16%), `--accent-subtle` (rgba 0.16/0.12), `--accent-text` (белый или почти чёрный по яркости)
- Темы хранятся в `localStorage` (`sw-custom-themes`), выбранная — в `electron-store` как `custom:<id>`
- При старте тема восстанавливается из конфига; если своя тема удалена, приложение откатывается на `dark`
- Свою тему можно редактировать и удалять; удаление активной темы сразу возвращает тёмную

### Караоке на весь экран

- Отдельный оверлей поверх всего окна (`position: fixed`, портал в `body`), запускается кнопкой в плеере или пунктом «Во весь экран» в панели текста
- Активная строка — крупно (32-96 px), соседние строки полупрозрачные; в фоне размытая обложка трека
- Сверху — название, исполнитель и индикатор точности синхронизации; снизу — пауза, следующий трек, полоса прогресса с перемоткой и размер шрифта
- `Space` — пауза, `Esc` — выход; отдельная кнопка переводит окно в нативный полноэкранный режим монитора
- Выход из нативного полноэкранного режима закрывает караоке (событие `leave-full-screen` -> IPC в renderer)
- Текст для режима подтягивается отдельно — караоке открывается без боковой панели
- Активная строка заливается слева направо по ходу звука: доля времени внутри строки
  идёт в CSS-переменную `--karaoke-progress`, градиент обрезается по `background-clip: text`
- Смена строки анимируется (`karaoke-line-in`): плавное появление и сдвиг

### Окно

- Своя рамка: `frame: false` у окна, системный заголовок и кнопки убраны
- Свои кнопки: свернуть, развернуть/восстановить, закрыть; иконка меняется при разворачивании
- Полоса заголовка — drag-зона (`-webkit-app-region: drag`), кнопки — `no-drag`
- Скруглённые углы: `roundedCorners` плюс цвет фона окна, совпадающий с темой
- Кнопка закрытия завершает приложение; сворачивание в трей осталось в меню трея

### Панель настроек

- Модальное окно с вкладками: «Внешний вид», «Текст и караоке», «Плеер», «Discord», «API для агентов», «О программе»
- Внешний вид: тема (встроенные и свои), анимации, плотность интерфейса, свёрнутый сайдбар при запуске
- Плеер: громкость, перемешивание и повтор при запуске
- Локальный API: вкл/выкл, порт, токен (показать, скопировать, перевыпустить)
- Настройки хранятся в `localStorage` (`sw-settings`) и применяются на лету: классы `no-animations` и `density-compact` на `documentElement`, состояние плеера — через `playerStore`

### Discord Rich Presence

- Свой клиент протокола Discord RPC (`electron/discord-rpc.ts`): именованный канал `discord-ipc-N`, кадры `[длина][опкод][JSON]`
- Handshake с `client_id`, команда `SET_ACTIVITY`, ответы `READY` и `PING`/`PONG`
- Активность обновляется из renderer: название трека, исполнитель, «пауза» и время с начала трека
- Переподключение при перезапуске Discord; при выходе из приложения активность снимается
- Требуется собственный Client ID приложения Discord — вписывается в настройках; имя большой картинки берётся из загруженного ассета

### Локальный API для агентов

- HTTP-сервер в main-процессе на `127.0.0.1` (порт 4783, при занятости — следующий свободный)
- Авторизация — Bearer-токен из `electron-store`; `/api/health` и `/api/openapi.json` открыты
- Проверка заголовка `Host` против локального адреса, CORS-заголовки не отдаются
- Команды уходят в renderer по IPC `agent-request` / `agent-response` и выполняются над сторами
- Информация для агента (URL, токен, OpenAPI, PID) пишется в `agent-api.json` в папке данных приложения

### Лайки

- Кнопка-сердечко у текущего трека в плеере и в строках списка
- Запись идёт от сессии пользователя: `PUT` / `DELETE` на
  `/users/{id}/system_playlist_likes/soundcloud:system-playlists:personalized-tracks:{id}:{trackId}`
  (так же работает веб-клиент SoundCloud)
- Ответ 500 на повторный `PUT` и 404 на `DELETE` отсутствующего лайка считаются
  достигнутым состоянием, а не ошибкой
- Список лайков синхронизируется с `likedTracks` в `appStore`

### Громкость колёсиком мыши

- Прокрутка над панелью плеера меняет громкость шагом 4%
- Рядом с ползунком всплывает подсказка с процентом, через 1.2 с исчезает

### Стили интерфейса

- Шесть оформлений: `classic`, `minimal`, `contrast`, `glass`, `threeD`, `bento`
- Переключаются в настройках и применяются на лету: атрибут `data-style` на `<html>`
- Правила лежат в `src/styles/styles.css` поверх базовых тем
- `bento` перестраивает главную страницу в модульную сетку плиток

### Плеер

- `playToken` защищает от гонки: пауза во время загрузки трека отменяет старт
- Громкость и mute независимы: громкость применяется к аудио всегда, а размут
  возвращает установленный уровень

- Создание/редактирование/удаление
- Добавление/удаление треков
- Drag & drop reorder

- Глобальный хоткей (play/pause)

### SoundCloud API (internal)

Приложение использует internal API веб-версии SoundCloud (`api-v2.soundcloud.com`). Запросы идут из main-процесса Electron: только там можно передать заголовки `Cookie` и `Authorization: OAuth <oauth_token>`, которые требует api-v2 для приватных коллекций.

**Основные endpoints:**
```
GET    /me                                     # Профиль
GET    /users/{id}/tracks                       # Мои треки
GET    /users/{id}/likes                        # Лайки
GET    /users/{id}/followings                   # Подписки
GET    /users/{id}/playlists                    # Плейлисты
GET    /users/{id}                             # Профиль пользователя
GET    /tracks/{id}                            # Информация о треке (media.transcodings)
GET    /tracks/{id}/related                     # Похожие треки (основа «Моей волны»)
GET    /charts?kind=trending&genre=...         # Популярное (без входа)
GET    /search?q=...&type=tracks|users|playlists # Поиск
GET    /playlists/{id}                         # Плейлист
```

> Путей вида `/me/likes` в api-v2 нет — они отдают 404. Приватные коллекции доступны только по `/users/{id}/...`.

**Stream URL:** `/tracks/{id}` отдаёт `media.transcodings`; запрос манифеста
(`.../stream/progressive?client_id=…`) возвращает подписанный URL файла на CDN — он играется напрямую.
Часть треков SoundCloud отдаёт только в HLS (`audio/mp4; codecs="mp4a.40.2"`) — такие потоки играются через `hls.js` (MSE).

### Хранение данных

- **Сессия:** cookies SoundCloud в разделе Electron `persist:soundcloud` (переживает перезапуск)
- **Настройки:** `electron-store` (тема, громкость, размер окна)
- **Тексты:** кеш Genius в `localStorage` (`sw-lyrics-cache`, 6 часов)
- **Свои темы:** `localStorage` (`sw-custom-themes`); выбранная тема — `custom:<id>` в `electron-store`
- **Настройки текста:** `localStorage` (`sw-lyrics-font`, `sw-lyrics-font-size`, `sw-lyrics-karaoke`)
- **Cache:** в памяти + optional disk cache для artwork
